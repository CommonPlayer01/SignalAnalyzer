# SignalAnalyzer 项目答辩要点

> 从「界面点击」到「文件读取 → 信号计算 → 曲线展示」的答辩讲解思路，配套高频问答。
> 依据当前代码整理，与 `SignalCoreLib-接口设计文档.md`、`SignalAnalyzer-调用流程.md` 保持一致。

---

## 0. 一句话定位（开场白）

> 这是一个基于 **Qt + CMake** 的桌面信号分析器：读取采样文本数据，做 **FFT、加窗、幅值谱/自功率谱、RMS** 计算并绘制曲线；核心算法抽成**不依赖 Qt 的独立静态库 `SignalCoreLib`**，界面层只做交互与绘图，通过**常驻后台线程 + 代际号机制**保证 UI 不卡顿。

开场即点出两个关键词：**「算法与界面解耦」** 和 **「后台线程防卡顿」**，这是整个项目的价值主张。

## 2. 核心亮点（评委最容易记住的点）

### 2.1 算法与界面彻底解耦

`SignalCoreLib` 是**纯 C++17 静态库**：零 Qt 依赖、零第三方 FFT 库（自己写的基 2 FFT）。好处：

- 可以被控制台程序、服务端、非 Qt 工程直接链接复用；
- 方便做**确定性测试**（不依赖 GUI 就能测）。

> 答辩金句：「核心算法是可复用的纯函数库，GUI 只是它的一个客户端。」配合冒烟测试 `SignalCoreLibSmokeTest`（控制台程序）佐证。

### 2.2 独立的 `Fft` 类

FFT 是**独立组件**，`SpectrumAnalyzer` 只做编排：`nextPowerOfTwo` 补零 → 加窗 → `Fft::forward` → 单边谱归一化。要点：

- **迭代实现**（位反转置换 + 蝶形运算，时域抽取），避免递归栈开销；
- `inverse(forward(x)) == x`（含 1/N 归一化），可当场说自洽性验证；
- **原地**运算，无额外分配。

> 评委若问「为什么自己写 FFT 不用库」，答：零依赖 + 可控 + 展示算法实现能力；接口极简（`Fft::Complex` 即 `std::complex<double>` 别名）。

### 2.3 线程模型 + 代际号（防卡顿的核心）

- 只有一个**常驻工作线程**，`ComputeTask`/`ScanTask` 都 `moveToThread` 过去，串行执行；
- 每次请求 `++generation`，任务在**读取前 / 循环中 / 发射结果前**检查 `isStale`，过期直接丢弃；
- **两个独立代际号**：`m_computeGeneration` 与 `m_scanGeneration` 分开，「切窗函数」不会打断「导入扫描」。

> 这回答了「界面为什么不会卡死」这个桌面项目必被问的问题。

### 2.4 设计模式（体现工程素养）

- **工厂模式** `WindowFactory`：`registerFactory/create/names`，新增窗函数只加一个类 + 注册一行，处理框架零修改（**开闭原则**）；
- **策略模式** `IWindow` 抽象：`name/apply/correctionFactor`；
- 注册表用**函数内静态对象**规避静态初始化顺序问题。

### 2.5 错误处理与确定性（体现严谨）

- 库内**不抛异常**，失败用 `ReadResult::ok` / `nullptr` / 空容器表达；
- 相同输入**逐位一致**输出，这是上自动化测试的前提。

## 3. 现场演示建议

演示别从「点按钮」开始，按以下顺序更能体现能力：

1. **冒烟测试先行**：`SignalCoreLibSmokeTest.exe` 返回 0，先证明「正确性」；
2. 运行 `ctest`，展示冒烟测试逐项通过（Fft/窗/SpectrumAnalyzer/RMS/SignalReader）；
3. 最后才开 GUI，导入 `samples/` 里的文件，演示：
   - `sine_100Hz_A2_fs1000_N1000.txt` → 谱峰应落在 100 Hz、幅值约 2.0（**当场验证算法正确性，很有说服力**）；
   - `dual_tone_200_500Hz_fs2000_N2048.txt` → 显示两个峰，说明频率分辨能力；
   - `sine_with_bad_lines_fs2560_N1024.txt` → 状态栏显示「跳过 N 个坏行」，证明鲁棒性；
   - 切换矩形窗 / 汉宁窗，观察频谱泄漏与旁瓣变化。

> 演示时同步说「谱峰频率对不对、幅值对不对、坏行有没有被正确跳过」，让评委看到你在验证而非只是展示。

## 4. 高频问答（提前准备答案）

| 可能的问题 | 参考回答要点 |
|---|---|
| **FFT 为什么必须 2 的整数次幂？** | 基 2 算法要求；非 2 幂用 `nextPowerOfTwo` 补零到最近 2 幂。 |
| **补零会不会影响结果？** | 频率分辨率不变（取决于真实采样时长），谱线更密；幅值按 `N_raw/N_fft` 被低估约 2.3%（见接口文档第 10 节量化），整周期采样可避免。 |
| **为什么要加窗？** | 非整周期截断产生频谱泄漏；加窗抑制旁瓣。 |
| **汉宁窗校正因子为什么是 2？** | 汉宁窗相干增益为 0.5，谱峰值除以增益（即乘 2）恢复真实幅值。 |
| **幅值谱 vs 自功率谱？** | 幅值谱是线性幅值，功率谱是幅值平方（单位幅值²）。 |
| **单边谱为什么 DC 和 Nyquist 用 `/N`，其余用 `2/N`？** | 除 DC、Nyquist 外，正负频率能量合并，需乘 2。 |
| **UI 为什么不会卡？** | 计算在常驻后台线程，UI 通过 `QueuedConnection` 收结果；不共享可变状态。 |
| **代际号机制怎么工作？** | 每次请求自增 generation，任务中途检查是否最新，过期即丢弃，避免旧结果覆盖新结果。 |
| **为什么 SignalCoreLib 不依赖 Qt？** | 可复用、可测试、职责单一；也是分层架构的体现。 |
| **线程安全怎么保证？** | 除 `WindowFactory` 注册表外全为无状态/纯函数，多线程只读安全；注册表启动期注册、之后只读。 |
| **为什么不用异常处理错误？** | 便于调用方就地判断、避免异常开销，错误用 `ok`/`nullptr` 表达，边界清晰。 |
| **怎么保证测试可靠？** | 确定性输出 + 构造已知信号（如整周期正弦）断言谱峰频率/幅值。 |
| **非 2 幂长度为什么幅值偏低？** | 归一化用的是补零后的 `N_fft` 而非 `N_raw`，见接口文档已知限制。 |
| **为什么自己写 FFT？** | 零第三方依赖、接口可控、展示算法实现能力。 |

## 5. 答辩结尾话术（主动收尾）

> 「本项目的工程价值在于三点：一是把信号分析算法封装成可复用的纯 C++ 库；二是用后台线程 + 代际号解决桌面端计算卡顿；三是用工厂/策略模式让窗函数可扩展、用确定性输出支撑自动化测试。已知不足包括：非 2 幂点数的幅值低估、不去直流/趋势，这些已在文档中明确，后续可引入加窗 + 整周期采样校验或去趋势预处理来改进。」

主动交代不足 + 给出改进方向，比被追问再解释更显成熟。
